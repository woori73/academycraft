## 3. 관찰 사항 (결함 아님, 운영 시 알아둘 것)
1. **권한·회원·학원 상태가 바뀌면 승인은 필터·인터셉터 단계에서 403 으로 막힌다.** 이때 계획 상태는 `PENDING` 으로 남고, **10분 안에 원래 상태로 복구되면 다시 승인 가능**하다(막혀 있는 동안은 실행되지 않음). 서비스 단계의 `INVALIDATED` 는 연결 지문·대상·저장 행이 달라진 경우에 기록된다(연결 변경·대상 변경·행 변조는 위 표처럼 실제 확인).
2. **현재 운영 버전(`543cdfc8`)으로 AcademyCraft 를 되돌리면 `writeApproved` 불리언 쓰기가 다시 열린다.** BuildIt 게이트웨이가 `/agent` 를 열기 전(현재 운영 BuildIt)에는 직접 로그인 사용자(`CHAT-01`)만 해당하지만, 롤백 수단으로는 **쓰기 긴급 차단 스위치를 우선**한다(아래 7단계).
3. 분당 생성 한도(10개)는 정책대로 동작한다. 대량 처리 용도로는 설계되지 않았다.
4. 검증 하네스에서 발견한 문제는 모두 하네스 쪽이었다(분당 한도에 걸린 스크립트, 한국어 패턴 정리 쿼리, 정적 화면 파일 미포함 환경). 수정 후 전부 재실행해 통과했다.
5. 로컬 환경에는 정적 화면(`frontend/`)을 별도 경로로 제공했다(운영은 별도 제공 방식). 이 항목은 화면 허용 목록·안내 페이지 동작만 확인했다.

## 4. 이 검증이 하지 않은 것 (미검증)
- 운영 환경(실제 AWS·ALB·실제 DB·실제 데이터)과 **실제 ADMIN/TUTOR 로그인 세션**
- Muse Spark 연동(P1-c 범위, 아직 없음)과 AI 비서 홈 화면(미구현)
- 다중 인스턴스 환경(게이트웨이 nonce 는 프로세스 메모리 — 승인 프로토콜은 이에 의존하지 않음)
- 이전 버전 중 P1-a 이전·`543cdfc8` 조합은 신규 BuildIt 과의 조합만 확인했다(구버전 BuildIt + 구버전 AcademyCraft 는 변경 전 기존 상태)
