# REA 학원관리 3단계 — AI 채팅 UI (CHAT-01)

> 화면: `frontend/screens/CHAT-01-ai-chat.html` (반응형 단일 HTML, 정적)
> 백엔드: `POST /api/rea/{academyId}/agent/execute`, `GET /api/rea/{academyId}/agent/tools` (2단계, 236개 테스트 PASS)
> 원칙: 정적 HTML이므로 `node --check`로 JS 문법 검증. 백엔드 변경 없음.

## 1. 화면 설명

### 레이아웃
- **헤더**: "AI 학원 비서" + 학원ID 입력(기본 1) + 인증키 입력칸 (X-Auth-Key). 인증키는 **localStorage**(`rea-chat-auth-key`)에 저장되어 새로고침 후에도 유지.
  역할 표시는 정적 안내("원장 · 강사 전용 (학부모 접근 불가)") — 학부모 계정은 Agent API에서 403.
- **도구 목록 (접기/펼치기)**: 7개 도구의 이름·설명·쓰기/읽기 표시·예시 명령. 예시 클릭 시 입력창에 자동 입력.
- **메시지 영역**: 사용자(우측 파란 말풍선) / Agent(좌측 흰색 말풍선).
- **입력 영역**: 텍스트 입력창 + 전송 버튼 + **"쓰기 승인" 토글 체크박스**.

### 동작 흐름
1. 자연어 명령 입력 (예: "오늘 결석한 학생을 정리해 줘")
2. X-Auth-Key 헤더와 함께 `POST /api/rea/{academyId}/agent/execute` 호출
   (`{command}` — P1-a 이후 쓰기 승인 토글은 없다. 쓰기는 서버 계획 승인으로만 실행)
3. 응답 렌더링
   - **성공**: 도구명 배지 + 도구별 읽기 쉬운 렌더링(표/막대 차트/요약 박스)
   - **requiresApproval=true**: "승인이 필요합니다" + **[승인하고 실행]** 버튼
     → 토글을 켜고 같은 명령을 재호출. 취소 가능.
   - **실패**: 오류 메시지 + 해결 방법 안내 (401 인증키 확인 / 403 권한 안내 / 파싱 실패 시 입력 예시)
   - **파싱 실패**: `suggestions`의 후보 도구들을 클릭 가능한 칩으로 표시 → 클릭 시 해당 도구의 예시 명령 입력
4. 쓰기 작업 결과는 변경 내역을 명시 (예: "학생 홍길동 등록됨, 인증키: abc123" + 복사 버튼)

### 도구별 결과 렌더링
| 도구 | 렌더링 |
|---|---|
| `getAbsentStudents` | 날짜·인원 수 + 표(이름, 반). 학부모 연락처는 API가 반환하지 않으므로 출결 명부·학생 관리 화면 링크 제공 |
| `analyzeGradeChanges` | 과목별 CSS 막대 차트(평균 득점률) + 추이(▲상승/▼하락/–유지) + summary 텍스트 + 성적 목록/학습 리포트 링크 |
| `generateOperationReport` | 활성 반·출결률·결석/지각/조퇴·공지/상담 건수 박스 + 상담 상태(진행중/답변완료/종료) + 보고서 텍스트 + 대시보드 링크 |
| `registerStudent` | 등록 정보 + 인증키 박스(복사 버튼) + 학생 관리 링크 |
| `assignStudentToClass` | 배정 결과 문구 + 반 상세/학생 관리 링크 |
| `getHomeworkIncomplete` | 반·미제출 인원 + 표(이름, 숙제) + 숙제 검사 화면 링크 |
| `createNoticeDraft` | 공지ID·제목 + "[초안] / 알림 미발송" 안내 + 공지 상세 링크 |

### 관리 화면 연결
결과에 `studentId`/`classId`/`noticeId`/`homeworkId`가 있으면 해당 관리 화면으로 이동하는 링크를 표시
(학생 관리 MBR-01 / 반 상세 CLS-03 / 공지 상세 NTC-04 / 숙제 목록 HW-03 등).
기존 33개 화면은 그대로 유지되며, 채팅은 보조 진입 경로 역할만 한다.

## 2. 대화 컨텍스트 동작 방식

- **보관 위치**: 페이지 세션 메모리(JS 변수 `turns`, `lastIds`). **localStorage가 아니며 페이지 리로드 시 초기화**된다.
- **보관량**: 최근 20개 턴(`MAX_TURNS = 20`). 초과 시 가장 오래된 것부터 삭제.
- **저장 항목**: 마지막 성공 실행 결과의 주요 ID — `studentId`, `studentName`, `classId`,
  `className`, `noticeId`, `homeworkId`, `authKey`.
- **지시어 감지**: 명령에 `아까/방금/그 학생/저 학생/그 아이/그 반/저 반/그 공지/저 공지/그 숙제`가
  포함되면 저장된 ID를 명령에 주입한다.
  - 예: "아까 등록한 학생 이름을 바꿔줘" → 실제 전송은 `"아까 등록한 학생 이름을 바꿔줘 (학생 12)"`
  - `CommandParser`는 "학생 12" 같은 숫자 패턴을 인식하므로 ID 추출이 쉬워진다.
  - 말풍선에는 원래 명령과 함께 `(→ 변환된 명령)` 형태로 표시한다.
- **한계**: 화면 단독 기능으로 실제 "이름 바꾸기" 도구는 없다. 서버 파서가 해당 명령을
  이해하지 못하면 파싱 실패 + 후보 도구 제안으로 안내한다.

## 3. 예시 대화 시나리오 3개

### 시나리오 A — 결석 확인 + 후속 질문 (컨텍스트)
1. 사용자: `오늘 결석한 학생을 정리해 줘`
2. Agent: [🛠 getAbsentStudents] "2026-10-13 결석 학생 3명" + 표 (이름/반)
3. 사용자: `아까 결석한 학생들 중에서 1반은?`
   → 컨텍스트는 ID 주입 중심이므로 이 경우 서버 파서가 날짜·반을 추출. 필요 시 "오늘 1반 결석 학생 조회"처럼 구체적으로 입력 안내.

### 시나리오 B — 쓰기 승인 흐름 (학생 등록)
1. 사용자: `학생 등록 김철수`
2. Agent: [🛠 registerStudent] ⚠️ 승인이 필요합니다 → [승인하고 실행] 클릭
3. Agent: ✅ 학생 **김철수** 등록됨 (학생ID: 14) + 인증키 `xxxx` [복사] 버튼
4. 사용자: `그 학생을 2반에 배정해줘`
   → 컨텍스트 적용: `"그 학생을 2반에 배정해줘 (학생 14)"` → assignStudentToClass 실행

### 시나리오 C — 성적 분석 + 운영 보고서 (읽기)
1. 사용자: `학생 5 성적 변화 추이`
2. Agent: [🛠 analyzeGradeChanges] 과목별 막대 차트 + 추이 + 요약 텍스트
3. 사용자: `최근 7일 운영 보고서 만들어줘`
4. Agent: [🛠 generateOperationReport] 출결률·공지·상담 통계 박스 + 보고서 텍스트

## 4. 인증 (1단계 보안 후속 과제)

- CHAT-01은 모든 API 호출에 **X-Auth-Key 헤더를 포함**한다 (1단계 후속 과제 이행).
- 401: 인증키 오류 안내 · 403: 학부모 거부/타 학원 접근 안내.
- ⚠️ **기존 33개 화면의 fetch에는 X-Auth-Key 헤더가 여전히 없다** — 이는 이번 단계 범위가 아니며
  별도 작업으로 분리한다 (보안카드/후속 이슈 참조).
